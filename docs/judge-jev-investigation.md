# Jev 决策模型调研与后续待尝试方向

> 状态：**已调研、暂不落地，列为后续待尝试改进方向**。
> 调研日期：2026-09-21。来源：TypeSafe 官网、LangChain《Jev as a Judge》实验、Arize 分析及独立测试。

## 一句话定性

Jev 不是新的 LLM，而是一类新的模型——**System One 决策模型**：不逐 token 生成文本，只对给定输入做**结构化判断**（选择 / 打分 / 是非），并返回**概率 + 置信度**。由前 OpenAI 研究员 Diogo Almeida（RLHF / InstructGPT 共同作者）创办的 TypeSafe 发布。

## 为什么它和本项目的评测相关

本项目的判分分两类：

- **确定性评估器**（工具轨迹、参数、JSON Schema）——代码判分，可复现、零成本。
- **LLM-as-Judge**（回答忠实度 `easyoffer_kb_groundedness` 等语义维度）——需要调用外部 LLM，有成本、有非确定性（同一答案评两次分数会抖）。

Jev 想替换的是**后者**：LLM-as-Judge 成本高、方差大，Jev 只做判断、不生成文本，因此**又稳又便宜**。

## 核心数据（判断是否值得引入）

| 维度 | Jev | 对比 |
| --- | --- | --- |
| 价格 | $0.042 / 百万输入 token，输出免费 | 比 LLM 便宜 40~445 倍 |
| 速度 | 端到端 70~500ms（多数 ~100ms） | 比 LLM 快 20~200 倍 |
| 输出 | 只返回 `Choice` / `Score` / `Noul` 三种类型化答案 + 概率 | LLM 逐 token 生成文本 |
| 准确率 | 官方 4 工作流 711 case 平均 67.8% | 落后最强模型 5~6 个点 |

三种判断原语：

- `Choice`：从最多 255 个候选项里选一个，返回各选项概率（和为 1）
- `Score`：在有序量表上打分，返回分数 + 分布
- `Noul`：是非判断，返回"是"的概率（0~1）

LangChain《Jev as a Judge》实验（窄域天气任务二元判定）：

- 与人工标签一致率 100%（Claude Sonnet 为 80%）
- 连续质量分数方差比 LLM 裁判低 92~913 倍
- 成本 $0.34 vs Claude 的 $28.17

## 三处必须注意的边界（引入前必须确认）

1. **"零幻觉"是文字游戏**：Jev 不会返回 schema 之外的答案，但在选项范围内照样会以高置信度答错。它不能"替代"评测，只能"更便宜地做粗筛"。
2. **概率不一定可信**：独立测试（Banking77 意图分类）发现，Jev 声称 80~95% 把握的样本实际正确率仅 64%。**不能直接拿它的概率当门槛**，需要用自己的数据重新校准。
3. **明确的能力边界**（官方列出 9 条弱点）：**不会算数、比大小、日期比较**——本项目"退款 30 天窗口""第 30 天 vs 第 31 天"这类边界值判断 Jev 完全做不了，必须留给代码；对抗性内容（prompt injection）会左右其答案，对客服安全场景是大坑。

## 对本项目的适配判断

| 环节 | Jev 能否用 | 理由 |
| --- | --- | --- |
| 确定性评估器（轨迹 / 参数 / schema） | 不适用 | 代码更准更便宜，这是 Jev 官方也明确的"不该用"场景 |
| LLM-as-Judge（回答忠实度 / 弃答判断） | **值得试** | 主战场，能降成本、降方差 |
| 边界值 / 退款窗口 / 数值类判断 | 禁止 | 官方明确不会算数 / 日期 |
| 幻觉陷阱的"弃答 vs 编造"判断 | 可试点 | 语义判断，但需重新校准概率门槛 |

## 后续待尝试方向（暂不落地）

1. 在 `easyoffer_kb_groundedness` 这个 Judge 上做**对照实验**：同一批 Case 分别用 LLM-as-Judge 与 Jev 判分，对比一致性、成本、方差。
2. 若对照结果达标，探索把 Jev 作为**低成本的粗筛层**叠加在 LLM-as-Judge 之前（Jev 快速判"明显过 / 明显不过"，只把模糊样本交给 LLM 复核）。
3. 用本项目自己的评测数据**重新校准 Jev 的概率门槛**，不直接采用其原生置信度。
